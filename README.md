# 순스테이 아침 브리핑 — 데이터 중계소

아침 브리핑 메일에 필요한 숫자(환율·날씨·바다)를 매일 새벽에 모아
`data/latest.json` 한 파일로 만들어 두는 저장소입니다.

## 왜 이게 필요한가

브리핑 메일은 클라우드에서 자동 발송됩니다. 그런데 그 클라우드 샌드박스는
바깥 인터넷을 **허용된 주소만** 열어주는 방식이라, 환율·날씨 사이트가 전부 막힙니다.

```
api.frankfurter.dev   ❌ 403
open-meteo            ❌ 403
badatime.com          ❌ 403
raw.githubusercontent ✅ 200   ← 유일하게 열린 문
```

그래서 **깃허브가 대신 데이터를 모아두고**, 브리핑은 이 저장소의 JSON 하나만
읽어 갑니다. PC를 켜둘 필요가 없습니다.

```
매일 04:20  GitHub Actions → collect.py 실행 → data/latest.json 커밋
     05:00  브리핑 루틴 → 이 JSON 읽기 → 메일 발송
```

## 담기는 것

| 항목 | 내용 | 출처 |
|---|---|---|
| 환율 | 원/달러 최신값, 전일 대비, 3개월 최고·최저, 그래프용 13점 | 유럽중앙은행 (frankfurter.dev) |
| 날씨 | 부산 시간별 기온·강수확률·풍속, 산책 좋은 시간, 주의 시간, 어제 대비 | Open-Meteo (기상청 모델) |
| 바다 | 해운대 06시 파고·수온, 당일 최대 파고, 수트 기준 | Open-Meteo Marine |

수집에 실패한 항목은 `errors` 배열에 남고, 브리핑에서는 "없음"으로 표기됩니다.
억지로 채우지 않습니다.

## 손볼 일이 생기면

- **발송 시각을 바꾸고 싶다** → `.github/workflows/collect.yml` 의 `cron` (UTC 기준, KST−9시간)
- **항목을 더하고 싶다** → `collect.py`
- **지금 당장 갱신하고 싶다** → 저장소 Actions 탭 → `브리핑 데이터 수집` → `Run workflow`

## 공개 저장소인 이유

브리핑 루틴이 토큰 없이 읽어야 해서 공개로 둡니다.
들어가는 건 **공개된 환율·기온·파고 숫자뿐**이며,
순스테이 사업 정보나 브리핑 본문은 이 저장소에 들어가지 않습니다.
